Physics

Finite-difference stencils, equation terms, and the Navier–Stokes solvers by Chorin projection and by the vorticity–streamfunction formulation.

Exported names and names declared public are listed here; the other names of the area are on the Internals page.

DifferenTT.derivative_coefficients — Method
derivative_coefficients(derivative_order::Int; stencil_order::Int=8) -> Dict{Int,Float64}

Return the coefficients $c_k$, $-4 \le k \le 4$, of the central finite-difference stencil of the derivative of order $m$ = derivative_order for a unit spacing,

\[\frac{d^m u}{dx^m}(x_i) \approx \frac{1}{h^m} \sum_{k=-4}^{4} c_k\, u_{i+k},\]

where $h$ is the grid spacing. Every operator of the library is built from these coefficients, as a band Toeplitz matrix (see onedim_differential_operator). The stencils have $q + 1$ points for the first and second derivatives, with $q$ = stencil_order, so the coefficients beyond $|k| = q/2$ are zero, and they are accurate to order $q$. The exception is the fourth derivative with $q = 8$, whose nine-point stencil is accurate to order 6. The first-derivative coefficients are antisymmetric, $c_{-k} = -c_k$, and the others symmetric.

Arguments

  • derivative_order::Int: 1, 2 or 4.

Keywords

  • stencil_order::Int=8: $q$, 2 or 8.

Throws

  • ArgumentError: for any other derivative or stencil order.

Examples

julia> c = DifferenTT.derivative_coefficients(2; stencil_order=2);
       [c[k] for k in -1:1]
3-element Vector{Float64}:
  1.0
 -2.0
  1.0

julia> c = DifferenTT.derivative_coefficients(1);
       [c[k] for k in 0:4]
5-element Vector{Float64}:
  0.0
  0.8
 -0.2
  0.0380952380952381
 -0.0035714285714285713

DifferenTT.wall_vorticity_coefficients — Method
wall_vorticity_coefficients(formula::Symbol) -> NTuple{3,Float64}

Return the coefficients $(c_1, c_2, c_U)$ of a wall vorticity formula for no-slip walls placed at ghost nodes,

\[\omega_\text{wall} = \frac{c_1 \psi_1 + c_2 \psi_2}{h^2} + \frac{c_U U}{h},\]

where $\psi_1$ and $\psi_2$ are the stream function at the first and second nodes away from the wall, with $\psi_\text{wall} = 0$, and $U$ is the tangential velocity of a moving wall, with $c_U$ taken for a top lid moving in $+x$.

In the vorticity–streamfunction formulation, the vorticity on a no-slip wall is not prescribed, so it is recovered from the stream function: expanding $\psi$ in a Taylor series at the wall, with $\psi = 0$ and $\partial \psi / \partial n$ given by the wall velocity, and using $\omega = -\Delta \psi$ there, gives Thom's first-order formula, $(c_1, c_2, c_U) = (-2, 0, -2)$, from the first node, and Jensen's second-order formula, $(-4, 1/2, -3)$, from the first two.

Arguments

  • formula::Symbol: :jensen for Jensen's formula, used by Kiffner & Jaksch (2023, Eq. (7)) and identical to Eqs. (3.4)–(3.5) of Ghia, Ghia & Shin (1982), or :thom for Thom's formula.

Throws

  • ArgumentError: for any other formula.

Examples

julia> DifferenTT.wall_vorticity_coefficients(:jensen)
(-4.0, 0.5, -3.0)

See also the boundary-condition tutorial Vorticity–streamfunction formulation.

DifferenTT.advection — Method
advection(fields::NTuple{N,MPS}, diff_ops::DifferentialOps{N}; cutoff::Float64=1e-15,
          maxdim::Int=typemax(Int64)) where N -> NTuple{N,MPS}

Return the advection term $(\mathbf{u} \cdot \nabla)\mathbf{u}$ of the velocity $\mathbf{u}$ = fields, in non-conservative form: component $i$ is $\sum_j u_j\, \partial_j u_i$, where $\partial_j u_i$ uses the first derivative of diff_ops built with the boundary conditions of component $i$. The products $u_j\, \partial_j u_i$ are element-wise products of MPS computed by tt_mul, and each sum is truncated with cutoff and maxdim.

See also diffusion, NavierStokesPredictorRHS.

DifferenTT.diffusion — Method
diffusion(fields::NTuple{N,MPS}, diff_ops::DifferentialOps{N}; cutoff::Float64=1e-15,
          maxdim::Int=typemax(Int64)) where N -> NTuple{N,MPS}

Return the diffusion term $\nabla^2 \mathbf{u}$ of the vector field $\mathbf{u}$ = fields: component $i$ is $\sum_j \partial_j^2 u_i$, with the second derivatives of diff_ops built with the boundary conditions of component $i$. These are the unweighted closures, as in kronecker_laplacian, since the term enters an explicit time step. The sums are truncated with cutoff and maxdim.

DifferenTT.equicorrelated_laplacian — Method
equicorrelated_laplacian(field::ScalarField{N}, grid::Grid{N}; correlation::Float64, stencil_order::Int=8,
                         maxdim::Int=typemax(Int), cutoff::Float64=0.0) where N -> MPO

Build the anisotropic diffusion operator $\nabla \cdot (K \nabla)$ with the equicorrelated diffusion tensor $K = (1 - \rho)\, \mathbb{I} + \rho\, \mathbf{1}\mathbf{1}^\top$, $\rho$ = correlation, i.e. minus the operator $\mathcal{L}(\rho)$ of Sec. 5.1 of Torrente et al., Factorized approximate inverse preconditioners in the tensor train format.

The Laplacian is the ideal case for separable preconditioners, such as the sinc preconditioner, which approximate $\mathcal{L}_0^{-1} = (-\Delta_h)^{-1}$. The equicorrelated tensor of Eq. (27) moves the problem away from that case in a controlled way, through a rotated anisotropy that is not aligned with any grid axis. Since $\mathrm{diag}(K) = \mathbb{I}$, centered finite differences give Eq. (28),

\[-\mathcal{L}(\rho) = \sum_{\ell=1}^N \partial_\ell^2 + 2\rho \sum_{\ell<m} \partial_\ell\, \partial_m,\]

where $\partial_\ell^2$ and $\partial_\ell$ are the second and first derivatives of onedim_differential_operator along axis $\ell$, i.e. $-\mathcal{A}_\ell$ and $\mathcal{C}_\ell$ of the paper. Even though the mixed term couples every pair of axes, we build the MPO directly from the pairwise finite-state machine of ndim_operator_sum_mpo (pair_ops), so its bond dimension is exactly 3 for any $N$ (Eq. (29)), and 2 for $\rho = 0$, where it reduces to the Laplacian of kronecker_laplacian.

$K$ is SPD for $-1/(N-1) < \rho < 1$, and for $\rho \ge 0$ the floor of Eq. (30), $\kappa(\mathcal{L}_0^{-1}\mathcal{L}) \le F(\rho, N) = (1 + (N-1)\rho)/(1 - \rho)$, holds, as derived in Appendix A of the paper. That derivation assumes stencil_order = 2, homogeneous Dirichlet sides and the spacing $h = 1/(n+1)$ of interior_grid; with Grid, $h = 1/(n-1)$, which only scales the operator. The default stencil_order = 8 builds the same structure with wider stencils, for which the bound is not proven.

Only TTArchitecture is supported. Neumann sides are not supported, since the weighting of the mixed term is not defined, and the Dirichlet lifts of scalar_dirichlet_correction only cover the second derivatives, so nonhomogeneous Dirichlet data are not fully supported either.

Keywords

  • correlation::Float64: $\rho$.
  • stencil_order::Int=8: $q$, 2 or 8 (2 in the paper).
  • maxdim::Int=typemax(Int), cutoff::Float64=0.0: truncation of the one-dimensional operators.

Throws

  • ArgumentError: if the architecture is not a TTArchitecture, or if field has a NeumannBC side.

Examples

arch = TTArchitecture(ntuple(_ -> 16, 3))
bc = BoundaryCond1d(DirichletBC(0.0), DirichletBC(0.0))
field = ScalarField(siteinds(arch), arch, BoundaryConditions(bc, bc, bc))
grid = interior_grid(arch, (1.0, 1.0, 1.0))
F, N = 10, 3
L = -1.0 * equicorrelated_laplacian(field, grid; correlation=(F - 1) / (F + N - 1), stencil_order=2)  # Eq. (32)
maxlinkdim(L)  # 3

DifferenTT.kronecker_laplacian — Method
kronecker_laplacian(field::ScalarField{N}, grid::Grid{N}; asymmetry::Float64=1.0, stencil_order::Int=8,
                    maxdim::Int=typemax(Int), cutoff::Float64=1e-15) where N -> MPO

Build the Laplacian $\Delta = \sum_i \partial_i^2$ of field as the Kronecker sum of the one-dimensional second derivatives of onedim_differential_operator, each closed with the boundary conditions of its axis (truncated at Dirichlet and open sides, mirrored at Neumann sides, wrapped on periodic axes) and scaled by $1/h_i^2$. The sum is assembled by ndim_operator_sum_mpo, whose bond dimension between axes is 2 (Kazeev & Khoromskij, 2012). Unlike symmetrized_laplacian, the Neumann rows are not weighted, so it is the consistent operator for explicit terms (e.g. the diffusion of the vorticity), but it is not symmetric with Neumann sides. Without Neumann sides, both functions return the same operator. asymmetry multiplies the second derivative along axis 1.

See also the boundary-condition tutorial Velocity–pressure formulation.

DifferenTT.symmetrized_laplacian — Method
symmetrized_laplacian(field::ScalarField{N}, grid::Grid{N}; asymmetry::Float64=1.0, stencil_order::Int=8,
                      maxdim::Int=typemax(Int), cutoff::Float64=1e-15) where N -> MPO

Build the Laplacian of field with its boundary closures, weighted on the Neumann rows so that it is symmetric.

The pressure and stream-function systems are solved with CG, so their operator must be SPD (after the sign change $A = -W\Delta$). The mirrored Neumann closure breaks the symmetry of the Laplacian, since it counts the boundary row twice. We therefore build the Kronecker sum $\Delta$ of kronecker_laplacian and, if field has a NeumannBC side, multiply the whole operator by the Neumann weight $W$ of neumann_weight_mpo, which gives the symmetric finite-volume half-cell operator $W\Delta$. The right-hand side must be weighted in the same way, with symmetrize_rhs. Without Neumann sides, $W = \mathbb{I}$ and the result is kronecker_laplacian. cutoff and maxdim truncate the operators and the product with $W$; the default cutoff keeps the operator exact.

Keywords

  • asymmetry::Float64=1.0: factor of the second derivative along axis 1, which gives the anisotropic operator $a\,\partial_1^2 + \sum_{i>1} \partial_i^2$.
  • stencil_order::Int=8: $q$, 2 or 8.
  • maxdim::Int=typemax(Int), cutoff::Float64=1e-15: truncation.

Examples

Δ = symmetrized_laplacian(p_field, grid; stencil_order=8)
A = -1.0 * Δ                                  # SPD for the paper's Chorin setup (Sec. 5.2)
b = symmetrize_rhs(p_field, -1.0 * div_u)     # weight the right-hand side with the same W

See also the boundary-condition tutorial Velocity–pressure formulation.

DifferenTT.INSExperiment — Type
INSExperiment(grid::Grid{N}, u_fields::VectorField{N}, p_field::ScalarField{N}, Re::Number,
              object_mask::Union{MPS,Nothing}; stencil_order::Int=8, maxdim::Int=100, cutoff::Float64=1e-8) where N

Incompressible Navier–Stokes experiment in the velocity–pressure formulation, solved by the Chorin projection.

The experiment describes the physical problem and its state: the grid, the velocity and pressure fields with their boundary conditions, the Reynolds number $Re$, an optional obstacle mask, and the stencil order and TT truncation of the evolution. The time integrator and the Poisson solver are passed to the scheme, chorin_evolve! or chorin_step, which follows the QTT pipeline of Peddinti et al. (2024) as described in Sec. 5.2 of Torrente et al., Factorized approximate inverse preconditioners in the tensor train format. The fields live on a collocated grid (Grid, with nodes at both ends), the obstacle enters by multiplying the velocity by the mask at every step, and the pressure system uses the compact Laplacian of symmetrized_laplacian rather than the composition of the discrete divergence and gradient, so the projected velocity is only approximately divergence-free.

The constructor checks that the velocity, the pressure and the mask share their site indices, and calls check_kolmogorov_scale.

Fields

  • grid::Grid{N}: the grid of the stored nodes.
  • u_fields::VectorField{N}: the velocity, initialized with its first state.
  • p_field::ScalarField{N}: the pressure, empty until the evolution stores it.
  • Re::Number: the Reynolds number.
  • object_mask::Union{MPS,Nothing}: the obstacle mask (1 in the fluid, 0 in the obstacle), or nothing.
  • stencil_order::Int: $q$, 2 or 8.
  • maxdim::Int: maximum bond dimension of the TT arithmetic of the evolution (operators, Poisson right-hand side, projection, time step). It is not the bond dimension of the solver.
  • cutoff::Float64: SVD cutoff of the same TT arithmetic. It is not the truncation or the stopping tolerance of the solver, which live on the solver itself.

Throws

  • ArgumentError: if object_mask is given and the site indices of the fields and the mask differ, or if grid flags an axis as periodic whose boundary conditions are not periodic.

Known limitations

The Chorin projection of v0.1 has two known limitations, which are recorded as @test_broken in the test suite and will be fixed in a later version:

  • Mean removal. When the pressure has no DirichletBC side, the Poisson system is singular and poisson_rhs makes its right-hand side consistent by subtracting a constant. That constant is $\sum_j b_j\, \prod_i h_i / \prod_i L_i = \sum_j b_j / \prod_i (n_i - 1)$ instead of the node mean $\sum_j b_j / \prod_i n_i$, so the mean of the right-hand side becomes $1 - \prod_i n_i/(n_i - 1)$ times its original value instead of zero, and the regularized system is not exactly consistent. This is inactive whenever the pressure has a Dirichlet side, as in the channel of Sec. 5.2 of the paper (Dirichlet outlet pressure).
  • Wall rows. The projection $\mathbf{u} = \mathbf{u}^* - dt\, \nabla p$ (∇p_correction) is applied to every row, including the $q/2$ rows next to the Dirichlet velocity faces that the time steppers otherwise keep fixed (BoundaryNull). The tangential pressure gradient therefore changes the boundary velocity a little at every step, which in the setup of Sec. 5.2 acts on the inlet rows.

Examples

arch = QTTArchitecture((7, 6))
inlet_outlet = BoundaryCond1d(DirichletBC(1.0), NeumannBC(0.0))
periodic = BoundaryCond1d(PeriodicBC(), PeriodicBC())
u_bcs = BoundaryConditions(inlet_outlet, periodic)
v_bcs = BoundaryConditions(BoundaryCond1d(DirichletBC(0.0), NeumannBC(0.0)), periodic)
p_bcs = BoundaryConditions(BoundaryCond1d(NeumannBC(0.0), DirichletBC(0.0)), periodic)
sites = siteinds(arch)
mask = …                                       # obstacle mask on `sites`, e.g. from crossinterpolate2
u_fields = VectorField((mask, zeros_mps(sites)), arch, (u_bcs, v_bcs))
grid = Grid(arch, (2.0, 1.0); periodic=DifferenTT.periodic_axes(p_bcs))   # period 1 in y
experiment = INSExperiment(grid, u_fields, ScalarField(sites, arch, p_bcs), 3000, mask)

See also ChorinCache, chorin_evolve!, and the boundary-condition tutorial Velocity–pressure formulation.

DifferenTT.cfl_spectral_radii — Method
cfl_spectral_radii(experiment::INSExperimentBase; vmax::Real=1.0) -> Tuple{Float64,Float64}

Return upper bounds on the spectral radii of the discretized advection and diffusion operators of experiment, from the coefficients of its finite-difference stencils (Gershgorin bound),

\[\lambda_\text{adv} = \sum_i \frac{v_\max}{h_i} \sum_k |c^{(1)}_k|, \qquad \lambda_\text{diff} = \sum_i \frac{1}{Re\, h_i^2} \sum_k |c^{(2)}_k|,\]

where $c^{(1)}$ and $c^{(2)}$ are the first- and second-derivative coefficients of derivative_coefficients and $v_\max$ = vmax bounds the velocity magnitude. The contributions of all axes add, since the time stepper advances the combined right-hand side. The bound is attained for the diffusion, whose coefficients alternate in sign so that the highest wavenumber reaches it, and is conservative for the advection.

Returns

  • (adv_eig, diff_eig): the bounds $\lambda_\text{adv}$ and $\lambda_\text{diff}$.

See also check_cfl.

DifferenTT.check_cfl — Method
check_cfl(experiment::INSExperimentBase, stepper::RK4; vmax::Real=1.0)
check_cfl(experiment::INSExperimentBase, stepper::ExplicitEuler; vmax::Real=1.0)

Check the linear stability (CFL) condition of experiment for the time step $dt$ of stepper, warn when it is violated, and log the result at @info level.

An explicit step is stable when $dt\,\lambda$ lies in the stability region of the scheme for every eigenvalue $\lambda$ of the linearized right-hand side. We bound these eigenvalues with cfl_spectral_radii: the central advection is skew-symmetric, so its eigenvalues lie on the imaginary axis, within $\lambda_\text{adv}$, and the diffusion is symmetric negative semidefinite, so its eigenvalues lie on the negative real axis, within $\lambda_\text{diff}$. For RK4, whose stability region reaches $2\sqrt{2}$ on the imaginary axis and $2.785$ on the negative real axis, the limits are

\[dt \le \frac{2\sqrt{2}}{\lambda_\text{adv}}, \qquad dt \le \frac{2.785}{\lambda_\text{diff}}.\]

The stability disk of forward Euler, $|1 + z| \le 1$, only touches the imaginary axis at the origin, so the central advection is never stable on its own and must be damped by the diffusion. For a Fourier mode with advection symbol $a$ and diffusion symbol $d$, the step is stable if and only if $dt \le 2d/(d^2 + a^2)$, and since the stencils satisfy $a^2 \le v_\max^2\, Re\, d$ (by the Cauchy–Schwarz inequality on the velocity vector), the sufficient limits are

\[dt \le \frac{2}{\lambda_\text{diff}}, \qquad dt \le \frac{2}{\lambda_\text{diff} + v_\max^2\, Re}.\]

Note that these are bounds for the linearized, constant-coefficient problem; the nonlinear flow and the TT truncation are not covered. vmax is the assumed maximum velocity magnitude of the flow.

See also check_kolmogorov_scale.

source
DifferenTT.check_kolmogorov_scale — Method
check_kolmogorov_scale(grid::Grid{N}, Re::Number) where N

DifferenTT.ChorinCache — Type
ChorinCache(experiment::INSExperiment{N}) where N
ChorinCache(u_diff_ops, p_diff_ops, u_boundary_null, poisson_op::MPO, regularize::Bool)

Operators of the Chorin projection that depend only on the experiment, built once per run.

The pressure operator is the same at every time step, since the obstacle only enters through the mask on the velocity, so it is built once, together with the velocity and pressure derivatives and the boundary projectors. The Poisson system for $p\,dt$ is

\[A = -W\Delta + c\,\mathbf{1}\mathbf{1}^\top,\]

where $W\Delta$ is symmetrized_laplacian and the rank-1 term, with $c = 2^{-N_s}$ for $N_s$ sites, is only added when the pressure has no DirichletBC side (regularization_check). Without it, $A$ would have the constant null space; with it, $A$ is SPD and the solution of a consistent system is the one of zero mean (for any $c > 0$). Note that $2^{-N_s}$ is the inverse number of nodes in QTT only. The first method builds every operator with the stencil order and the truncation of experiment; the second takes them directly, to reuse operators built elsewhere.

Fields

  • u_diff_ops: the velocity derivatives (DifferentialOps).
  • p_diff_ops: the pressure derivatives (DifferentialOpsScalar).
  • u_boundary_null: the velocity boundary projectors (BoundaryNull).
  • poisson_op::MPO: the operator $A$ above.
  • regularize::Bool: whether the rank-1 term was added.

See also poisson_rhs, chorin_step, and the boundary-condition tutorial Velocity–pressure formulation.

DifferenTT.NavierStokesPredictorRHS — Type
NavierStokesPredictorRHS(experiment::INSExperimentBase, u_diff_ops, u_boundary_null) <: AbstractRHS

Right-hand side of the predictor of the Chorin projection, Eq. (33) of Torrente et al., Factorized approximate inverse preconditioners in the tensor train format,

\[\partial_t \mathbf{u} = \frac{1}{Re} \nabla^2 \mathbf{u} - (\mathbf{u} \cdot \nabla)\mathbf{u},\]

as a callable for the explicit time steppers: rhs(u::Tuple, t, stage) returns, for every component $i$, $Z_i \left( \frac{1}{Re} \nabla^2 u_i - (\mathbf{u} \cdot \nabla) u_i \right)$, with the advection and diffusion of u_diff_ops and the projector $Z_i$ of u_boundary_null (see BoundaryNullScalar), which keeps the Dirichlet boundary rows of the velocity fixed. It does not depend on t or stage. The truncation is that of experiment.

Fields

  • experiment::E: the experiment (Re, cutoff, maxdim).
  • u_diff_ops::D: the velocity derivatives (DifferentialOps).
  • u_boundary_null::B: the velocity boundary projectors (BoundaryNull).

See also AbstractRHS, chorin_step.

DifferenTT.chorin_evolve! — Method
chorin_evolve!(experiment::INSExperiment{N}, solver::AbstractLinearSolver, stepper::AbstractExplicitStepper,
               save_every::Int=1, logger=nothing, log_filename::String="chorin_log") where N

Run the time evolution of experiment with the Chorin projection, storing the velocity and the pressure in its fields.

We check the CFL condition (check_cfl), build the ChorinCache once, and advance the last stored velocity stepper.time_evol_kwargs.nsteps times with chorin_step. The fields keep the initial velocity and the velocity and pressure of the steps save_every, 2 save_every, … and of the last step, which is always stored; the last stored state is also the input of the next step. As explained in chorin_step, the stored velocities are the provisional fields of the next step. If logger is given, the fields and the residual norms of the stored pressure solves (linsolve_errorlog) are written to log_filename with log_data.

Arguments

  • experiment::INSExperiment{N}: the experiment, with its initial velocity stored and its pressure empty.
  • solver::AbstractLinearSolver: the solver of the pressure system (ALS, ResidualALS, GlobalCG, …), with its truncation and stopping criteria in its sweep_kwargs and updater_kwargs.
  • stepper::AbstractExplicitStepper: the integrator of the predictor (ExplicitEuler, RK4); its TimeEvolArgs set the time step and the number of steps.
  • save_every::Int=1: the interval, in steps, between stored states.
  • logger=nothing: a SimpleLogger, or nothing to write nothing.
  • log_filename::String="chorin_log": the name of the JLD2 file in the directory of logger.

Throws

  • ArgumentError: if the velocity has no stored state, if the pressure has one, or if save_every < 1.

DifferenTT.chorin_step — Method
chorin_step(experiment::INSExperiment{N}, cache::ChorinCache, u_mpss::NTuple{N,MPS}, solver::AbstractLinearSolver,
            stepper::AbstractExplicitStepper, t::Real) where N -> Tuple

Advance the velocity u_mpss by one time step $dt$ = stepper.time_evol_kwargs.dt with the Chorin projection (Chorin, 1967), as in the QTT pipeline of Peddinti et al. (2024) and Sec. 5.2 of Torrente et al., Factorized approximate inverse preconditioners in the tensor train format.

The step proceeds as follows. We first multiply the velocity by the obstacle mask (mask_correction). We then solve the pressure Poisson system of poisson_rhs with solver, starting from the last pressure stored in experiment, and project the masked velocity, $\mathbf{u} = \mathbf{u}^* - dt\, \nabla p$ (∇p_correction). Finally, we advance the projected velocity over $dt$ with the explicit predictor of NavierStokesPredictorRHS and stepper. Note the order: each step projects the velocity it receives and then predicts, so the velocity it returns is the provisional field $\mathbf{u}^*$ of the next step, which is not projected, and the pressure is the one of the projection at the start of the step. This order follows the pipeline of Peddinti et al. (2024), where the mask is applied right before the projection. We are aware that the order predict, mask, project, which returns the projected velocity, is the more natural one; since it applies the same sequence of operations, shifted by a projection of the initial velocity, it would solve the same pressure systems, and it may replace the current order in a future version. The splitting is first-order accurate in $dt$ whatever stepper is, and the projected velocity is only approximately divergence-free (see INSExperiment, including its known limitations). experiment is not modified; storing the results is left to the caller.

Arguments

  • experiment::INSExperiment{N}: the experiment. Its last pressure, if any, is the initial guess of the solve.
  • cache::ChorinCache: the operators of the experiment.

DifferenTT.poisson_rhs — Method
poisson_rhs(experiment::INSExperiment{N}, cache::ChorinCache, masked_u_mpss::NTuple{N,MPS}, dt::Real) where N -> MPS

Build the right-hand side of the pressure Poisson system of the Chorin projection, Eq. (34) of Torrente et al., Factorized approximate inverse preconditioners in the tensor train format, solved for $p\,dt$.

Imposing $\nabla \cdot \mathbf{u}_{n+1} = 0$ on the projected velocity gives $\Delta (p\,dt) = \nabla \cdot \mathbf{u}^*$. The truncated Laplacian misses the Dirichlet values of the pressure on the ghost nodes, and the rows of the divergence next to the Dirichlet velocity faces are not consistent, so the right-hand side of the system $A\,(p\,dt) = \mathbf{b}$ of ChorinCache is

\[\mathbf{b} = W \left( -Z\, \nabla \cdot \mathbf{u}^* + dt\, C\mathbf{1} \right),\]

where $Z$ is the projector of divergence_dirichlet_correction, $C$ the Dirichlet lift operator of scalar_dirichlet_correction for the second derivative (the ghost values of $p\,dt$ are $dt$ times the pressure values), and $W$ the Neumann weight of symmetrize_rhs. If cache.regularize, a constant is then subtracted to make the singular system consistent, which is one of the known limitations of INSExperiment (the constant is not the node mean).

Arguments

  • experiment::INSExperiment{N}: the experiment, whose truncation is used.
  • cache::ChorinCache: the operators of the experiment.
  • masked_u_mpss::NTuple{N,MPS}: the velocity $\mathbf{u}^*$, already multiplied by the obstacle mask.
  • dt::Real: the time step.

DifferenTT.INSVorticityExperiment — Type
struct INSVorticityExperiment{N} <: INSExperimentBase

Two-dimensional incompressible Navier–Stokes experiment without obstacles in the vorticity–streamfunction formulation (Kiffner & Jaksch, 2023), with one VorticityFace per side of the domain: no-slip walls (possibly moving), slip walls, inflows, outflows and periodic faces.

The formulation evolves the vorticity $\omega = \partial_x v - \partial_y u$ by the transport equation of VorticityTransportRHS, and recovers the velocity from the stream function, $u = \partial_y \psi$, $v = -\partial_x \psi$, which solves $-\Delta \psi = \omega$. The velocity is therefore discretely divergence-free by construction, without a pressure projection. The experiment describes the physical problem only: the time integrator and the Poisson solver are passed to the scheme, vorticity_evolve! or vorticity_step.

Walls and inflow faces are ghost nodes one spacing outside the stored nodes, and outflow faces are the last stored node, so grid must be built with vorticity_grid (or interior_grid for four ghost faces). The boundary-condition types of both fields must match the faces (vorticity_boundary_conditions).

Fields

  • grid::Grid{N}: Grid of the stored nodes.
  • omega_field::ScalarField{N}: Vorticity ω = ∂ₓv - ∂ᵧu.
  • psi_field::ScalarField{N}: Stream function ψ, with u = ∂ᵧψ, v = -∂ₓψ.
  • Re::Number: Reynolds number.
  • faces::NTuple{2, Tuple{VorticityFace, VorticityFace}}: Faces faces[axis] = (left, right).
  • vmax::Float64: Characteristic speed of the flow, used by the CFL check.
  • wall_formula::Symbol: Wall vorticity formula, :jensen (second order, as in Kiffner & Jaksch, 2023) or :thom (first order).
  • stencil_order::Int: Order of the finite difference stencils (only 2 is supported).
  • maxdim::Int: Maximum bond dimension allowed throughout the simulation.
  • cutoff::Float64: SVD cutoff performed throughout the simulation.

See also the boundary-condition tutorial Vorticity–streamfunction formulation.

DifferenTT.InflowFace — Type
InflowFace(; psi, omega=0.0, normal_velocity)

Inflow face with a prescribed velocity profile, a ghost node one spacing outside the stored nodes with $\psi$ = psi and $\omega$ = omega on it, which carries the advective flux normal_velocity * omega into the domain. Each value is a constant or a profile (see VorticityFace).

psi, omega and normal_velocity must belong to the same velocity profile, and psi must match the psi of the adjacent walls, since the difference of $\psi$ between two walls is the flow rate between them. For example, the parabolic profile of a left inflow into a channel of height $H$, with walls $\psi = 0$ (bottom) and $\psi = 2UH/3$ (top), is

\[u = \frac{4Uy(H - y)}{H^2}, \qquad \psi = U \left( \frac{2y^2}{H} - \frac{4y^3}{3H^2} \right), \qquad \omega = -\frac{4U(H - 2y)}{H^2}.\]

See also the boundary-condition tutorial Vorticity–streamfunction formulation.

DifferenTT.VorticityCache — Type
VorticityCache(experiment::INSVorticityExperiment{N}; cutoff::Float64=1e-15, maxdim::Int=typemax(Int64)) where N

Operators and static boundary terms of the vorticity–streamfunction scheme that depend only on the experiment, built once per run.

Every face fixes $\psi$ and $\omega$ on its ghost nodes, and the truncated operators take those ghost values as zero. Ghost values that depend on $\psi$ (the wall vorticity) become the operator wall_op, and static ghost values become lifts that are added to the right-hand sides: psi_lift and velocity_lift from the face values of $\psi$, wall_source from moving walls, walls with $\psi \ne 0$ and inflow vorticity, and advection_lift from the inflow fluxes. The operators and lifts are built with their own tight cutoff, not with experiment.cutoff, so that the boundary entries are not truncated away.

Fields

  • diff_ops: First and second derivative operators of the stream function (DifferentialOpsScalar), for the velocity.
  • omega_diff_ops: First and second derivative operators of the vorticity, for the advection. Same as diff_ops but with the upwind outflow rows, see outflow_advection_closure.
  • laplacian::MPO: Laplacian of the stream function, weighted on the Neumann (outflow) rows: W Δψ, see symmetrized_laplacian.
  • omega_laplacian::MPO: Unweighted Laplacian of the vorticity, see kronecker_laplacian. Equal to laplacian without outflow faces.
  • poisson_op::MPO: Operator A = -W Δ of the stream function Poisson system (plus the pin c 𝟏𝟏ᵀ if regularize). It is symmetric positive definite.
  • wall_op: Ghost contribution of the wall vorticity of the no-slip walls to Δω that depends on ψ, see wall_vorticity_operator. nothing without no-slip walls.
  • wall_source: Static ghost contribution of the faces to Δω: moving walls, walls with ψ ≠ 0 and inflow vorticity.
  • psi_lift: Ghost contribution of the face values of ψ to Δψ.
  • velocity_lift: Ghost contribution of the face values of ψ to (∂ₓψ, ∂ᵧψ).
  • advection_lift: Ghost advective flux of the inflow faces.
  • regularize::Bool: Whether ψ has no ghost face, so that the Poisson system is singular and is pinned to zero mean.

The static terms are nothing when they vanish.

See also the boundary-condition tutorial Vorticity–streamfunction formulation.

source
DifferenTT.VorticityFace — Type
abstract type VorticityFace

Boundary face of an INSVorticityExperiment, given per axis as faces[axis] = (left, right).

In the vorticity–streamfunction formulation, every face fixes the conditions of both $\psi$ and $\omega$ at once, and the boundary-condition types of the two fields follow from it (vorticity_boundary_conditions). Walls and inflows (NoSlipWall, SlipWall, InflowFace) are ghost nodes one spacing outside the stored nodes, an OutflowFace is the last stored node, and a PeriodicFace wraps the axis.

The face data follow three conventions:

  • A profile is a Vector of values at the stored nodes along the face, in increasing node index of the other axis, i.e. of length variable_dims(arch)[3 - axis]; a Number is a constant value.
  • The tangential velocity of a face of axis 2 is $u$, and that of a face of axis 1 is $v$, signed in the $+$ direction of the other axis.
  • The normal velocity of a face of axis $i$ is the velocity component along axis $i$, signed in the $+$ direction of that axis (positive on a left inflow).

See also the boundary-condition tutorial Vorticity–streamfunction formulation.

DifferenTT.VorticityTransportRHS — Type
VorticityTransportRHS(experiment::INSExperimentBase, cache, u::MPS, v::MPS, source) <: AbstractRHS

Right-hand side of the vorticity transport equation in conservative form,

\[\partial_t \omega = -\partial_x(u\omega) - \partial_y(v\omega) + \frac{1}{Re}(\Delta\omega + s),\]

as a callable for the explicit time steppers, rhs((ω,), t, stage) -> (dω/dt,), with the velocity $(u, v)$ and the wall vorticity source $s$ frozen over the stages of the time integrator. The advective fluxes through the walls vanish because the normal velocity does, so the truncated stencils (ghost value 0) give them exactly. The inflow fluxes come from cache.advection_lift, and the outflow faces use the upwind rows of cache.omega_diff_ops (see outflow_advection_closure). The diffusion uses the unweighted cache.omega_laplacian, since it is an explicit term. The products $u\omega$ and $v\omega$ are computed by tt_mul.

Fields

  • experiment::E: The experimental setup (Re, cutoff, maxdim).
  • cache::C: Precomputed operators (VorticityCache).
  • u::MPS, v::MPS: Velocity components.
  • source: Wall vorticity source s, see wall_vorticity_source. nothing if there is none.

See also the boundary-condition tutorial Vorticity–streamfunction formulation.

poisson_rhs(experiment::INSVorticityExperiment, cache::VorticityCache, omega::MPS) -> MPS

DifferenTT.vorticity_evolve! — Method
vorticity_evolve!(experiment::INSVorticityExperiment{N}, solver::AbstractLinearSolver,
                  stepper::AbstractExplicitStepper, save_every::Int=1, logger=nothing,
                  log_filename::String="vorticity_log") where N

Run the time evolution of experiment with the vorticity–streamfunction scheme, storing the vorticity and the stream function in its fields.

We check the CFL condition (check_cfl, with experiment.vmax), build the VorticityCache once, and advance the last stored vorticity stepper.time_evol_kwargs.nsteps times with vorticity_step. The fields keep the initial vorticity and, for the steps save_every, 2 save_every, … and the last step, which is always stored, the vorticity at the end of the step and the stream function solved at its start; the last stored vorticity is also the input of the next step. If logger is given, the fields and the residual norms of the stored stream-function solves (linsolve_errorlog) are written to log_filename with log_data.

Arguments

  • experiment::INSVorticityExperiment{N}: the experiment, with its initial vorticity stored and its stream function empty.
  • solver::AbstractLinearSolver: the solver of the stream-function system (ALS, ResidualALS, GlobalCG, …).
  • stepper::AbstractExplicitStepper: the integrator of the transport (ExplicitEuler, RK4); its TimeEvolArgs set the time step and the number of steps.
  • save_every::Int=1: the interval, in steps, between stored states.
  • logger=nothing: a SimpleLogger, or nothing to write nothing.
  • log_filename::String="vorticity_log": the name of the JLD2 file in the directory of logger.

Throws

  • ArgumentError: if the vorticity has no stored state, if the stream function has one, or if save_every < 1.

Examples

stepper = RK4(; time_evol_kwargs=TimeEvolArgs(0.0, 1.0, 100), cutoff=1e-12, maxdim=32)
solver = …                                          # e.g. ALS or GlobalCG
vorticity_evolve!(experiment, solver, stepper, 10)  # stores the initial state and the steps 10, 20, …, 100
