Utilities

Logging of simulation data, visualization of fields, and the switch of the precompilation workload. The visualize_* methods need Plots to be loaded.

Exported names and names declared public are listed here; the other names of the area are on the Internals page.

DifferenTT.timeit_to — Constant
timeit_to::TimerOutput

Global timer of DifferenTT. The solvers and the Navier–Stokes steppers time their main phases with TimerOutputs.@timeit_debug timeit_to "…", which costs nothing unless the debug timings are enabled with enable_debug_timings!. Print the collected timings with show(timeit_to), and clear them with TimerOutputs.reset_timer!(timeit_to).

source
DifferenTT.Logger — Type
abstract type Logger

Supertype of the data loggers of the evolutions (chorin_evolve!, vorticity_evolve!), which store their fields and residuals with log_data. Not to be confused with Logging.AbstractLogger: these loggers write data files, not log messages.

source
DifferenTT.SimpleLogger — Type
SimpleLogger(log_dir::String)

Logger that writes JLD2 files into the directory log_dir; build it with init_logger, which creates the directory.

Note that the standard library Logging also exports a SimpleLogger (a log-message handler). After using DifferenTT, Logging the unqualified name is ambiguous and throws an UndefVarError, so it must be written DifferenTT.SimpleLogger or Logging.SimpleLogger. The functions of DifferenTT only need the object that init_logger returns, so most scripts never write the name.

Fields

  • log_dir::String: the directory of the files.

DifferenTT.enable_debug_timings! — Method
enable_debug_timings!() -> nothing

Turn on the @timeit_debug sections of DifferenTT, which then record their timings in timeit_to.

This calls TimerOutputs.enable_debug_timings(DifferenTT), which redefines a function inside the package, so the timed methods are recompiled at their next call. Call it once, before the run to be profiled, and turn the timings off again with disable_debug_timings!.

DifferenTT.init_logger — Method
init_logger(log_dir::String) -> SimpleLogger

Return a SimpleLogger that writes into the directory log_dir, creating it (and its parents) if it does not exist.

Examples

logger = init_logger(joinpath("results", "cavity"))
vorticity_evolve!(experiment, solver, stepper, 10, logger, "run1")  # writes results/cavity/run1.jld2

DifferenTT.log_data — Method
log_data(logger::SimpleLogger, filename::String, key::String, value)
log_data(logger::SimpleLogger, filename::String, data::Dict)
log_data(logger::Nothing, filename::String, key::String, value)
log_data(logger::Nothing, filename::String, data::Dict)

Write value under key, or every pair of data, into the JLD2 file filename (with the extension .jld2 added if it is missing) in the directory of logger. If the file exists, the other keys are kept and an existing key is overwritten; otherwise the file is created. With logger = nothing nothing is written, so that the evolutions can call it unconditionally.

Examples

logger = init_logger(mktempdir())
log_data(logger, "run", "residuals", [1e-3, 1e-6])
log_data(logger, "run", Dict("Re" => 100.0, "dt" => 1e-3))   # same file, run.jld2

DifferenTT.visualize_scalar — Function
visualize_scalar(mps::MPS, grid::Grid{N}, arch::Architecture, save_path=nothing; npoints=50, slice_dims=(1, 2),
                 slice_vals=nothing, kwargs...)
visualize_scalar(field::ScalarField{N}, grid::Grid{N}, save_path=nothing; npoints=50, slice_dims=(1, 2),
                 slice_vals=nothing, kwargs...)
visualize_scalar(field::ScalarField{N}, step::Int, grid::Grid{N}, save_path=nothing; npoints=50, slice_dims=(1, 2),
                 slice_vals=nothing, kwargs...)

Plot a scalar field sampled on npoints points per dimension of grid.

In one dimension we draw a scatter plot, and in two dimensions a heatmap. For $N \geq 3$ we draw a heatmap of the two-dimensional slice spanned by slice_dims, with every other coordinate fixed at the sample nearest to the corresponding entry of slice_vals, or at the middle sample if slice_vals is nothing. The ScalarField methods plot the last stored time step, or the time step step. If save_path is a String, the figure is also saved there, creating its directory if needed. The remaining keywords are passed to Plots.jl.

These methods are defined in the package extension DifferenTTPlotsExt and require using Plots; without it, a MethodError with a hint is thrown.

Returns

  • Plots.Plot: the figure.

Examples

using Plots
visualize_scalar(experiment.p_field, experiment.grid, "figures/pressure.png"; npoints=128)

visualize_vector(mpss::NTuple{N,MPS}, grid::Grid{N}, arch::Architecture, save_path=nothing; npoints=20,

Plot the magnitude of a vector field as a heatmap on npoints points per dimension, overlaid with a quiver plot of its components on quiver_npoints points per dimension, scaled by arrow_scale.

For $N \geq 3$ we plot the two-dimensional slice spanned by slice_dims, with every other coordinate fixed at the middle sample; slice_vals is currently ignored. The VectorField methods plot the last stored time step, or the time step step. If save_path is a String, the figure is also saved there. The remaining keywords are passed to Plots.jl.

These methods are defined in the package extension DifferenTTPlotsExt and require using Plots. One-dimensional fields throw an ArgumentError.

DifferenTT.visualize_vorticity — Function
visualize_vorticity(mpss::NTuple{N,MPS}, grid::Grid{N}, arch::Architecture, save_path=nothing; npoints=50,
                    quiver_npoints=20, arrow_scale=1.0, slice_dims=(1, 2), kwargs...)
visualize_vorticity(field::VectorField{N}, grid::Grid{N}, save_path=nothing; npoints=50, quiver_npoints=20,
                    arrow_scale=1.0, slice_dims=(1, 2), kwargs...)
visualize_vorticity(field::VectorField{N}, step::Int, grid::Grid{N}, save_path=nothing; npoints=50,
                    quiver_npoints=20, arrow_scale=1.0, slice_dims=(1, 2), kwargs...)

Plot the vorticity of a velocity field as a heatmap, overlaid with a quiver plot of the velocity.

We sample the velocity on npoints points per dimension and evaluate the vorticity on the interior samples by second-order central differences, with spacing box_size[i] / (npoints - 1); the boundary samples are set to zero. In two dimensions we plot the scalar vorticity $\partial_x v - \partial_y u$, and in three the magnitude of the vorticity vector, on the slice spanned by slice_dims through the middle sample. The VectorField methods plot the last stored time step, or the time step step. If save_path is a String, the figure is also saved there. The remaining keywords are passed to Plots.jl.

These methods are defined in the package extension DifferenTTPlotsExt and require using Plots. The vorticity is only defined for two or three components, so any other N throws an ArgumentError.

Returns

  • Plots.Plot: the figure.

DifferenTT.set_precompile_workload — Method
set_precompile_workload(enabled::Bool; default_environment::Bool=false) -> Bool

Turn the precompilation workload of DifferenTT on (true, the default) or off (false).

When the package is precompiled, i.e. after it is installed or updated and after every change to its source, we run its common paths on small problems: the QTT operators, the local and global solvers, the FAI preconditioner, cross interpolation and the Navier–Stokes steps. The native code compiled for them is stored with the package, so that the first calls of every later session load it instead of compiling it, which makes them several times faster. The price is about two minutes of precompilation instead of a few seconds. When the source changes often, e.g. while developing the package, we recommend to turn the workload off.

The setting is the preference precompile_workload of DifferenTT, stored in the LocalPreferences.toml of the active environment, or, with default_environment = true, of the default environment @v#.#, which every environment whose load path includes it inherits; the setting of the active environment takes precedence. Julia records the preference with the precompiled package, so the change takes effect in a new session: restart Julia, and the next using DifferenTT precompiles the package again.

Examples

DifferenTT.set_precompile_workload(false)                            # in the active environment
DifferenTT.set_precompile_workload(false; default_environment=true)  # in every environment of this machine
DifferenTT.set_precompile_workload(true)                             # back to the default
