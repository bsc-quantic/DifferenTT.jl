Time evolution

Time steppers for the semi-discrete systems built by the Physics module.

Exported names and names declared public are listed here; the other names of the area are on the Internals page.

DifferenTT.AbstractTimeStepper — Type
abstract type AbstractTimeStepper

Supertype of the time integration schemes. Every concrete stepper stores its time interval and step in a field time_evol_kwargs::TimeEvolArgs (see TimeEvolArgs).

source
DifferenTT.TimeEvolArgs — Type
TimeEvolArgs(ti::Float64, tf::Float64, dt::Float64, nsteps::Int)
TimeEvolArgs(ti::Float64, tf::Float64, nsteps::Int)
TimeEvolArgs(ti::Float64, tf::Float64, dt::Float64)

Time interval and step of an evolution, stored in an AbstractTimeStepper as time_evol_kwargs, from which timestep reads the step and the evolution loops (chorin_evolve!, vorticity_evolve!) read the number of steps and the initial time.

Given the number of steps, the step is $dt = (t_f - t_i)/n_\text{steps}$. Given the step, the number of steps is rounded, $n_\text{steps} = \mathrm{round}((t_f - t_i)/dt)$, while dt and tf are kept as given, so $t_i + n_\text{steps}\, dt$ can differ from $t_f$ by up to $dt/2$; the evolution loops run nsteps steps of size dt. The times must be Float64 and nsteps an Int, which is what tells the last two methods apart.

Fields

  • ti::Float64: the initial time.
  • tf::Float64: the final time.
  • dt::Float64: the time step.
  • nsteps::Int: the number of steps.

Examples

julia> TimeEvolArgs(0.0, 1.0, 4)
TimeEvolArgs(0.0, 1.0, 0.25, 4)

julia> TimeEvolArgs(0.0, 1.0, 0.3)
TimeEvolArgs(0.0, 1.0, 0.3, 3)

DifferenTT.AbstractRHS — Type
abstract type AbstractRHS

Supertype of the right-hand sides $\mathbf{f}(\mathbf{u}, t)$ of the explicit time steppers, for systems $\partial_t \mathbf{u} = \mathbf{f}(\mathbf{u}, t)$.

A subtype is a callable struct that holds whatever it needs to evaluate the right-hand side (operators, boundary terms, the experiment) and implements the interface

(rhs::MyRHS)(u::Tuple, t::Real, stage::Int) -> Tuple

which takes the state u, a tuple of MPS with one entry per field component, the time t, and the stage stage of the stepper (1 to 4 for RK4, 1 for ExplicitEuler; it may be ignored), and returns a tuple of MPS of the same length as u. The library's right-hand sides are NavierStokesPredictorRHS and VorticityTransportRHS. The example below wraps a user-defined rhs_custom_func and keeps the Dirichlet boundary rows fixed, as NavierStokesPredictorRHS does.

Examples

struct SampleRHS{E,D,B} <: AbstractRHS
    experiment::E
    u_diff_ops::D
    u_boundary_null::B
end

function (rhs::SampleRHS)(u, t, stage)
    cutoff = rhs.experiment.cutoff
    maxdim = rhs.experiment.maxdim
    rhs_terms = rhs_custom_func(u, rhs.u_diff_ops; cutoff=cutoff, maxdim=maxdim)
    # Keep the boundary rows fixed
    return ntuple(length(u)) do i
        deleter = rhs.u_boundary_null[i].u_row_deleter
        isnothing(deleter) ? rhs_terms[i] : apply(deleter, rhs_terms[i]; cutoff=cutoff, maxdim=maxdim)
    end
end

DifferenTT.ExplicitEuler — Type
ExplicitEuler(; time_evol_kwargs::TimeEvolArgs, kwargs...)

Forward (explicit) Euler scheme, $\mathbf{u}_{n+1} = \mathbf{u}_n + dt\, \mathbf{f}(\mathbf{u}_n, t_n)$, first-order accurate in $dt$. The keyword arguments other than time_evol_kwargs (e.g. cutoff, maxdim) are stored as the TT truncation of the sums of timestep. Its stability limits are those of check_cfl.

Fields

  • time_evol_kwargs::TimeEvolArgs: the time interval and step.
  • tt_kwargs::K: the TT truncation keywords, as a NamedTuple.

Examples

stepper = ExplicitEuler(; time_evol_kwargs=TimeEvolArgs(0.0, 1.0, 100), cutoff=1e-10, maxdim=64)

DifferenTT.RK4 — Type
RK4(; time_evol_kwargs::TimeEvolArgs, kwargs...)

Classical fourth-order Runge–Kutta scheme,

\[\mathbf{u}_{n+1} = \mathbf{u}_n + \frac{dt}{6} (\mathbf{k}_1 + 2\mathbf{k}_2 + 2\mathbf{k}_3 + \mathbf{k}_4),\]

where $\mathbf{k}_1 = \mathbf{f}(\mathbf{u}_n, t_n)$, $\mathbf{k}_2 = \mathbf{f}(\mathbf{u}_n + \frac{dt}{2}\mathbf{k}_1, t_n + \frac{dt}{2})$, $\mathbf{k}_3 = \mathbf{f}(\mathbf{u}_n + \frac{dt}{2}\mathbf{k}_2, t_n + \frac{dt}{2})$ and $\mathbf{k}_4 = \mathbf{f}(\mathbf{u}_n + dt\,\mathbf{k}_3, t_n + dt)$. The keyword arguments other than time_evol_kwargs (e.g. cutoff, maxdim) are stored as the TT truncation of every sum of timestep. Its stability limits are those of check_cfl.

Fields

  • time_evol_kwargs::TimeEvolArgs: the time interval and step.
  • tt_kwargs::K: the TT truncation keywords, as a NamedTuple.

DifferenTT.timestep — Function
timestep(stepper::ExplicitEuler, u::Tuple, rhs_func::AbstractRHS, t::Real=0.0) -> Tuple
timestep(stepper::RK4, u::Tuple, rhs_func::AbstractRHS, t::Real=0.0) -> Tuple

Advance the state u from time t by one step $dt$ = stepper.time_evol_kwargs.dt with the explicit scheme stepper (ExplicitEuler or RK4), and return the new state.

Every stage evaluates rhs_func(u, t, stage), and every linear combination of MPS is a sum truncated with the TT keywords of stepper (stepper.tt_kwargs), so the accuracy of a step is bounded by that truncation as well as by the order of the scheme. Note that the boundary conditions enter only through rhs_func (e.g. the rows that BoundaryNullScalar keeps fixed).

Arguments

  • stepper::AbstractExplicitStepper: the scheme, with the step and the TT truncation.
  • u::Tuple: the state, a tuple of MPS with one entry per field component.
  • rhs_func::AbstractRHS: the right-hand side, called as rhs_func(u, t, stage) (see AbstractRHS).
  • t::Real=0.0: the time of u.

Examples

stepper = RK4(; time_evol_kwargs=TimeEvolArgs(0.0, 0.1, 10), cutoff=1e-12, maxdim=32)
u_next = timestep(stepper, (u,), rhs, 0.0)
